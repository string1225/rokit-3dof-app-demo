# Rokid 3DoF 诊断与续航测试 · v0.3.1

适用于所提供 `GlassesBareDevSample.zip` 对应的 Rokid 开发机：Android 12+、480×640、黑底单绿色显示，安全区 Y=80..560。应用直接运行在眼镜上，提供3DoF文字维稳/抖动诊断，以及自动五阶段续航测试。无需手机或网络；续航媒体阶段使用本机麦克风和摄像头。

## 使用

1. 安装 `outputs/rokid-3dof-demo-debug.apk`：

   ```powershell
   adb install -r outputs/rokid-3dof-demo-debug.apk
   adb shell am start -n com.rokid.stabledemo/.MainActivity
   ```

2. 启动显示「3DoF 测试」与「续航测试 · 25分钟」。触屏直接选；眼镜单击切换选项、双击选中进入、长按退出应用。Rokid 将双击编码为 BACK，因此专用菜单内的返回事件用于进入选项；系统 Home 可以离开应用。
3. 进入3DoF后保持头部静止片刻；有效姿态就绪后开始打字。转头时先快速补偿，画面偏离中心后再逐步回到眼镜正前方；歪头时继续横滚反向补偿，保持IMU重力方向对应的水平。
4. 3DoF内单击切换「维稳开／关」，文字与播放进度继续；长按立即水平回中（不吸收横滚）；双击/返回停止并保存。下方显示曲线、频率、RMS、绘制频率及延迟估计。

原始 IMU 备用路径会显示约三秒的初始化提示。无可用传感器时显示错误，单击重试。数据断流时等待切换数据源或长按重新连接。3DoF进入后台会停止传感器并保存本段记录；回到前台重新初始化与回正，创建新记录。续航测试离开前台会中止并保存，不自动续跑。

## 水平缓慢回中

v0.3将文字平面的默认中心对准480×480安全视口中心，即整屏的(240,320)。偏离中心后，独立的yaw/pitch锚点缓慢跟随头部视线；横滚不参与慢跟随，继续用最新姿态补偿。文字会逐步回到正前方，不再永久留在最初的朝向。

默认跟随时间常数1.5秒、合成角速度上限12°/秒；小到中等偏移约3–5秒靠近中心，更大偏移需要更久。回中速度不等于补偿速度：本帧仍直接使用最新姿态，没有对整个头部姿态增加1.5秒的低通。当前尚未加入姿态预测或临近扫描重投影，因此也不宣称已达到硬件允许的最低延迟。

慢回中会主动改变世界锚点，因此长期留在正前方不等于IMU绝对航向没有漂移；帧日志保留锚点角度，便于区分主动跟随与跟踪误差。

按需可调整回中参数：

```powershell
adb shell am force-stop com.rokid.stabledemo
adb shell am start -n com.rokid.stabledemo/.MainActivity --ef follow_tau_seconds 1.5 --ef follow_speed_deg_s 12
```

`follow_tau_seconds` 范围0.2–10，越小回中越快；`follow_speed_deg_s` 范围1–60，仅限制锚点移动，不限制抖动/横滚的快速补偿。恢复前台或更换传感器参考系会重新建立跟随基准。

v0.3.1修正启动时轻微歪头会被保留为固定倾斜的问题。Android旋转矢量和Fusion ENU均以世界+Z为上方；现在从融合姿态恢复重力方向，建立+Y朝上的渲染参考系，初始俯仰/横滚继续参与补偿。第一帧只对视线方向回中，长按、切回维稳和缓慢回中均不吸收横滚。水平基准取自传感器，尚未标定IMU与光学显示之间的装配偏角，也未在目标眼镜上验证本版的光学水平。

## 诊断曲线与延迟

- 实线：系统融合姿态的上下俯仰角；虚线：根据预计显示时刻对齐后，计算出的残余姿态误差。两条线使用同一角度尺度，显示最近4秒。
- 残差利用后续IMU样本插值到已提交帧的预计呈现时刻，再计算 `该帧目标锚点的逆 × 实际姿态 × 已提交补偿姿态的逆`。主动回中不计为抖动。它是软件模型估计，不是摄像头或光学测量，也没有把同一姿态相减来制造一条恒零曲线。帧日志额外记录锚点yaw/pitch角度以便复核。
- 抖动主频是频带内功率最大频点；均频是功率加权的频谱均值。最近4秒的信号去线性趋势后加Hann窗，分析0.5–20 Hz，并根据实际采样频率限制上界。至少约2秒有效数据才输出频率；RMS低于0.02°、样本不足或断流时显示 `--`。它会包含该频带内有意的头部动作，不能自动证明都是传感器噪声。
- 输入/残差RMS均去除固定偏移和线性趋势。绘制Hz按帧数除实际经过时间计算，避免卡顿时高估帧率。
- 样本年龄：IMU采集时间戳到本帧CPU绘制结束。绘制耗时：本次自绘CPU耗时。预计显示延迟约为「采集到绘制开始 + max(CPU绘制、FrameMetrics应用帧耗时) + 一个刷新周期」，标注约一帧时间假设的不确定度。
- 这不能测出完整运动到光子延迟。传感器内部、融合滤波、合成器和光学扫描的额外延迟仍需外部高速拍摄/标记测量。界面数值用于软件链路比较，不作为真机总延迟保证。

## 自动续航测试

首次进入仅请求相机与麦克风权限，授权后自动运行一轮；每阶段有效工作300秒，初始化和媒体收尾另计：

| 顺序 | 负载 | 保存内容 |
| --- | --- | --- |
| 1 | 纯显示循环打字机 | 电量与系统遥测 |
| 2 | 相同显示＋麦克风持续采集 | 采样量/格式；PCM读出后丢弃 |
| 3 | 相同显示＋连续播放生成音频 | 音频格式；保持现有媒体音量 |
| 4 | 相同显示＋摄像头无声录像 | AVC MP4，不含音轨 |
| 5 | 相同显示＋每10秒拍照 | 相机就绪立即拍一张，此后每10秒一张JPEG |

五阶段显示策略一致且不启用IMU，以减少额外变量。保持前台和屏幕常亮；亮度、媒体音量保持原设置。音量为零/静音、权限缺失、硬件失败、存储失败等会明确停止并保存失败原因，不以纯显示冒充相应负载。双击/返回可中止。

测放电时应断开充电；USB连线或充电状态适合验收功能，不能据此推算放电耗能。每5秒及阶段边界采集电量%、电压、温度、电流、电量计和热状态；不支持的字段留空。摘要包含整轮及各阶段首末读数、带符号的变化、充电标记、有效采样覆盖时间，以及可用时的梯形积分能量和平均功率。`observed_*` 是整机观测变化，`discharging_only_*` 仅在全部观测均为未插电放电时提供；没有应用独占的精确功耗归因。

## 记录与导出

3DoF与续航都会创建独立会话。结束或中止后导出报告至：

```text
Download/RokidTests/<日期时间-随机ID>/
```

包含 `samples.csv`（电池原始采样）、`summary.json`（阶段耗电摘要）、`metadata.json`、`stages.jsonl`（工作负载与开关/回正事件）。3DoF会额外导出 `motion_frames.csv` 和 `motion_metrics.csv`；关闭写入器后再复制，保证最后一批数据完整。

视频、照片以及原始报告保存在应用目录，导出失败时仍保留原件：

```text
/sdcard/Android/data/com.rokid.stabledemo/files/power-tests/<会话ID>/
```

可用 `adb pull /sdcard/Download/RokidTests` 取回报告；用 `adb pull /sdcard/Android/data/com.rokid.stabledemo/files/power-tests` 取回媒体和全部原始文件。电量百分比粒度较粗，短阶段的0%变化不等于真实耗电为0；电流不可用时不会填造W/Wh。

## 实现方式与开源依据

- 保留参考 Demo 的画布、安全区、按键和广播事件定义。3DoF路径不启动摄像头或麦克风，媒体硬件仅由续航模式使用。
- 优先使用 Android `TYPE_GAME_ROTATION_VECTOR`，其次 `TYPE_ROTATION_VECTOR`。后一种可能受磁场影响。传感器注册失败、首次数据超时或持续断流时自动尝试下一数据源。
- 无融合姿态时，将眼镜本机陀螺仪与加速度计接入 [x-io Fusion](https://github.com/xioTechnologies/Fusion)，采用 MIT 开源的无磁力计 AHRS 与静止零偏估计。C 源码随仓库固定在 commit `a8d7224f36a0ec82345ef49a3db50e65f8d3bab8`，通过 JNI 运行，包含 arm64-v8a、armeabi-v7a、x86_64。
- 在独立线程读取传感器采集时间戳，绘制时取最新姿态。用四元数逆旋转和透视单应变换补偿整块文字平面，包含偏航、俯仰与横滚；不将欧拉角简单换成像素位移。内容离开视场时自然裁切。
- 按 VSync 由硬件 Canvas 渲染。文字按完整文本预排版，以单调时钟每 90 ms 增加一个 Unicode 字符，全部显示后停留 2400 ms，持续循环。切换模式与回正不重置播放。
- 未添加姿态预测或厂商重投影接口。显示端仍有传感器、绘制、合成与扫描输出延迟，需要真机观察后再决定预测参数。

没有加入研究文档中的 SLAM/VIO/Gyroflow：此版本的输入是本机 IMU，目标是虚拟文本方向稳定。

## 真机必须确认的两个参数

**轴向：** 根据用户实机反馈，v0.1中的旧Demo映射会把偏航与横滚交换。v0.2默认使用标准Android屏幕坐标：右X、上Y、朝向佩戴者Z，pitch=X、yaw=Y、roll=Z。若测试另一种旧固件，可显式设置 `axes=demo`，恢复保持右手性的旧基变换 `(x,y,z) → (x,z,-y)`。

**视场角：** 资料没有光学内参或真实 FOV。默认水平 30° 是待校准的工程初值，不能当作设备规格。参数指 480×480 安全显示区对应的水平视角；假设方形像素和安全区中心为主点。真实设备若存在光学畸变、非对称投影或显示区映射差异，需替换为测量后的投影参数。

可通过启动参数调整，不增加启动页按钮：

```powershell
# 参数仅作用于这次启动；先停止已有进程再设置。
adb shell am force-stop com.rokid.stabledemo
adb shell am start -n com.rokid.stabledemo/.MainActivity --es axes android --ef horizontal_fov_deg 30

# 强制走 Fusion 原始六轴，用于比较系统融合与开源算法。
adb shell am force-stop com.rokid.stabledemo
adb shell am start -n com.rokid.stabledemo/.MainActivity --ez force_fusion true
```

`axes` 支持 `android`（默认）或 `demo`；FOV 范围为5°..120°，非法值回退30°。需要永久修改时调整 `MainActivity` 默认配置并重新构建。

缩时验收可显式启动 `--ei benchmark_stage_seconds 12`，每项12秒，菜单与报告均标记该时长；未传参数仍是每项300秒。缩时运行只能验证流程，不能替代25分钟真机续航测量。

## 构建与测试

需要 JDK 17+（本机验证为 Android Studio JBR 25）、Android SDK 36、NDK `28.2.13676358`、CMake `3.22.1`。Gradle wrapper 为 9.5.0，AGP 为 9.3.0。首次构建需要下载 AndroidX 和 JUnit。

```powershell
./tools/build.ps1

# 指定本机路径
./tools/build.ps1 -AndroidSdk 'C:/Users/yourname/AppData/Local/Android/Sdk' -JavaHome 'C:/Program Files/Android/Android Studio/jbr'

# 对明确指定的测试设备额外安装和运行仪器测试（含真实媒体的缩时一轮）
./tools/build.ps1 -DeviceSerial emulator-5580
```

脚本执行单元测试、Lint、APK构建、签名验证，并将APK、SHA-256和检查记录写到 `outputs/`。带 `-DeviceSerial` 的仪器测试会实际使用麦克风、扬声器、相机并保存测试媒体，测试媒体音量须非零；完整测试包含12秒×5阶段。原始Gradle产物在 `app/build/outputs/apk/debug/`。输出目录不提交到Git，源代码与固定版本开源依赖提交到仓库。

## 真机检查流程

| 动作 | 应观察到的行为 |
| --- | --- |
| 正视后进入3DoF | 自动回正，绿色中文逐字出现并循环 |
| 小幅左右转头 | 维稳开启时先快速反向补偿，再逐步回到视野中心；关闭时随眼镜屏幕转动 |
| 抬头、低头 | 文字按相反方向补偿，幅度应与真实视场匹配 |
| 左右歪头 | 文字执行横滚反向旋转 |
| 单击比较 | 播放不重启，状态条显示开／关 |
| 长按 | 文字立即回到当前正前方，横滚补偿继续保留 |
| 大幅转头 | 文字自然离开有限视场，不能贴在屏幕边缘 |
| 双击/返回 | 返回唯一开始按钮，停止传感器 |
| 切后台再回来 | 重新初始化与回正，避免跨暂停积分 |
| 静止一至五分钟 | 观察静止抖动与航向漂移，记录数据源、采样率与回正次数 |

屏幕上的 Hz 是姿态样本到达频率的估计，**不是端到端延迟或维稳精度**。模拟器验证能够检查代码与交互，不能确认眼镜的光学效果、功耗、真实漂移和运动到显示延迟。IMU 3DoF 不补偿走动产生的位置变化；无可靠航向参考时仍会产生漂移。
