# Rokid 3DoF 诊断与续航测试 · v0.5.0

适用于所提供 `GlassesBareDevSample.zip` 对应的 Rokid 开发机：Android 12+、480×640、黑底单绿色显示，安全区 Y=80..560。应用直接运行在眼镜上，提供3DoF文字维稳/抖动诊断，以及自动五阶段续航测试。无需手机或网络；续航媒体阶段使用本机麦克风和摄像头。

## 使用

1. 安装 `outputs/rokid-3dof-demo-debug.apk`：

   ```powershell
   adb install -r outputs/rokid-3dof-demo-debug.apk
   adb shell am start -n com.rokid.stabledemo/.MainActivity
   ```

2. 首页有「3DoF 测试」「续航测试 · 25分钟」「预测补偿 · 开/关」「浮窗跟随 · 开/关」「IMU 录制 · 开/关」。预测和跟随默认开，IMU录制每次启动默认关；后三项只切换设置，选择第一项开始3DoF。跟随选择会保存。触屏直接选；眼镜单击循环五项、双击选中、长按退出。Rokid 将双击编码为 BACK，因此专用菜单内的返回事件用于选中；系统 Home 可以离开应用。
3. 进入3DoF后保持头部静止片刻；有效姿态就绪后开始7行循环打字。跟随开时，转头先快速补偿，范围内逐步回到黑色内容区中央；浮窗中心在X或Y任一方向偏移超过内容区宽/高的50%时，直接跳回内容区中心。跟随关时，锚点固定在本段跟踪的相对方向，不慢跟随、不越界回中，单击切换维稳也不移动锚点；长按才手动回中。歪头时继续横滚反向补偿，保持IMU重力方向对应的水平。
4. 3DoF内单击切换「维稳开／关」，文字与播放进度继续；长按立即水平回中（不吸收横滚）；双击/返回停止并保存。下方显示曲线、频率、RMS、绘制频率及延迟估计。

原始 IMU 备用路径会显示约三秒的初始化提示。无可用传感器时显示错误，单击重试。数据断流时等待切换数据源或长按重新连接。3DoF进入后台会停止传感器并保存本段记录；回到前台重新初始化与回正，创建新记录。续航测试离开前台会中止并保存，不自动续跑。

跟随关时浮窗可以离开视野，转回原方向会重新看到；需要移到眼前时长按回中。固定的是IMU参考系中的锚点，不能消除传感器本身的漂移。进入新会话、后台恢复或传感器切换建立新参考系时仍会初始化锚点。

## 水平自动回中

v0.3.3将回中位置改为上下参数栏之间的黑色内容区中心。480×640整屏中，内容区为X=0..480、Y=160..392，中心为(240,276)，高度232；整体硬件安全区Y=80..560中还包含参数栏，不再全部计入浮窗活动范围。文字增加到7行，边框高度根据实际排版加上下留白计算，并在内容区内居中；浮窗绘制也裁剪到这块区域，避免覆盖参数。

仅在「浮窗跟随 · 开」时：在慢跟随之前计算浮窗中心的屏幕投影，只要X偏移超过内容区宽的50%（240像素），或Y偏移超过内容区高的50%（116像素），就在当前帧将yaw/pitch锚点移到当前视线，同时把两个位置方向回中。恰好50%仍走慢跟随；判定使用实际FOV和屏幕轴，歪头时也一致。目标已在视野后方时也直接回中，避免画面滞留在视野外。回中保留横滚补偿及打字进度；屏幕短暂提示「超界 · 已水平回中」。关闭跟随同时禁用慢跟随和超界回中。

未超界时默认跟随时间常数1.5秒、合成角速度上限12°/秒，小到中等偏移约3–5秒靠近中心。回中速度不等于补偿速度：本帧仍使用最新真实姿态驱动跟随，没有对整个头部姿态增加1.5秒的低通；满足条件时，快速补偿额外应用下述短时俯仰预测。尚无厂商临近扫描重投影，也不宣称达到硬件最低延迟。

慢回中会主动改变世界锚点，因此长期留在正前方不等于IMU绝对航向没有漂移；帧日志保留锚点角度，便于区分主动跟随与跟踪误差。

按需可调整回中参数：

```powershell
adb shell am force-stop com.rokid.stabledemo
adb shell am start -n com.rokid.stabledemo/.MainActivity --ef follow_tau_seconds 1.5 --ef follow_speed_deg_s 12
```

`follow_tau_seconds` 范围0.2–10，越小回中越快；`follow_speed_deg_s` 范围1–60，仅限制锚点移动，不限制抖动/横滚的快速补偿。恢复前台或更换传感器参考系会重新建立跟随基准。

v0.3.1修正启动时轻微歪头会被保留为固定倾斜的问题。Android旋转矢量和Fusion ENU均以世界+Z为上方；现在从融合姿态恢复重力方向，建立+Y朝上的渲染参考系，初始俯仰/横滚继续参与补偿。第一帧只对视线方向回中，长按、切回维稳和缓慢回中均不吸收横滚。水平基准取自传感器，尚未标定IMU与光学显示之间的装配偏角，也未在目标眼镜上验证本版的光学水平。

## 周期俯仰预测

v0.4增加本项目实现的单频周期预测，无新增第三方依赖。x-io Fusion仍负责备用六轴融合；预测器读取融合后的真实姿态。在传感器线程用最近约3.5秒数据拟合正弦/余弦、偏置和线性趋势，每100ms更新模型；绘制只读取不可变快照，不等待拟合。

首版识别1–8Hz稳定俯仰，要求至少3个周期、连续稳定频率及较高拟合质量，振幅范围0.04–5°；静止和非周期动作保持普通补偿。识别需要几个周期，静止时显示「正在识别稳定周期」正常。预测强度缓入，失锁快速衰减；突发转头、大残差或超过80ms采样断流会清空模型。关闭预测时也不执行模型训练。

只把模型预测的俯仰增量加到最新真实姿态上，不用拟合值替换真实姿态，不预测yaw/roll。采集时刻到目标时刻的总预测限制20ms，额外修正限制0.75°；样本到绘制开始超过25ms时不预测。默认目标为绘制开始后15ms，总时长包含样本年龄。慢跟随、50%越界回中均使用实测姿态，预测不会主动移动锚点。参考系切换/后台恢复后重新识别周期。

首页第三项可开/关，返回后重新进入3DoF对比。界面显示识别周期、实际强度与总前推毫秒；现有单击维稳开关、长按回中、双击返回不变。也可显式启动：

```powershell
adb shell am force-stop com.rokid.stabledemo
adb shell am start -n com.rokid.stabledemo/.MainActivity --ez prediction_enabled true --ef prediction_lead_ms 15
```

`prediction_lead_ms`为绘制开始之后的工程目标时间，范围5–20ms；实际总预测仍受20ms上限约束。它没有经过眼镜显示延迟标定，不会直接采用界面上较粗的显示延迟估算。规律性纯上下位移不属于本版预测能力。频段是模型启用范围，不代表已经在目标眼镜上证明该范围内都稳定。

## 诊断曲线与延迟

- 实线是系统融合的俯仰输入，点线是未启用预测时的普通补偿残差估计，虚线是当前实际采用的补偿残差估计。三条线使用同一角度尺度，显示最近4秒；普通与当前的RMS用于对比预测收益。预测关闭或未锁定时，两条残差重合正常。
- 残差利用后续IMU样本插值到已提交帧的预计呈现时刻，再计算 `该帧目标锚点的逆 × 实际姿态 × 已提交补偿姿态的逆`。主动回中不计为抖动。它是软件模型估计，不是摄像头或光学测量，也没有把同一姿态相减来制造一条恒零曲线。帧日志额外记录锚点yaw/pitch角度以便复核。
- 普通补偿对照使用同一帧、同一预计呈现时刻及同一锚点，仅去掉预测增量；不是拿两次不同头部运动的日志相减。当前残差的呈现时间估算沿用实际帧遥测，可能与保守的20ms预测窗口不同，因此眼镜实测对比仍然必要。
- 抖动主频是频带内功率最大频点；均频是功率加权的频谱均值。最近4秒的信号去线性趋势后加Hann窗，分析0.5–20 Hz，并根据实际采样频率限制上界。至少约2秒有效数据才输出频率；RMS低于0.02°、样本不足或断流时显示 `--`。它会包含该频带内有意的头部动作，不能自动证明都是传感器噪声。
- 输入/残差RMS均去除固定偏移和线性趋势。绘制Hz按帧数除实际经过时间计算，避免卡顿时高估帧率。
- 样本年龄：IMU采集时间戳到本帧CPU绘制结束。绘制耗时：本次自绘CPU耗时。预计显示延迟约为「采集到绘制开始 + max(CPU绘制、FrameMetrics应用帧耗时) + 一个刷新周期」，标注约一帧时间假设的不确定度。
- 这不能测出完整运动到光子延迟。传感器内部、融合滤波、合成器和光学扫描的额外延迟仍需外部高速拍摄/标记测量。界面数值用于软件链路比较，不作为真机总延迟保证。

## 自动续航测试

首次进入仅请求相机与麦克风权限，授权后自动运行一轮；每阶段有效工作300秒，初始化和媒体收尾另计：

| 顺序 | 负载 | 保存内容 |
| --- | --- | --- |
| 1 | 纯显示循环打字机 | 电量与系统遥测 |
| 2 | 相同显示＋麦克风持续采集 | 采样量/格式；PCM读出后丢弃 |
| 3 | 相同显示＋连续播放生成音频 | 音频格式；保持现有媒体音量 |
| 4 | 相同显示＋摄像头无声录像 | AVC MP4，不含音轨 |
| 5 | 相同显示＋每10秒拍照 | 相机就绪立即拍一张，此后每10秒一张JPEG |

五阶段显示策略一致且不启用IMU，以减少额外变量。保持前台和屏幕常亮；亮度、媒体音量保持原设置。音量为零/静音、权限缺失、硬件失败、存储失败等会明确停止并保存失败原因，不以纯显示冒充相应负载。双击/返回可中止。

测放电时应断开充电；USB连线或充电状态适合验收功能，不能据此推算放电耗能。每5秒及阶段边界采集电量%、电压、温度、电流、电量计和热状态；不支持的字段留空。摘要包含整轮及各阶段首末读数、带符号的变化、充电标记、有效采样覆盖时间，以及可用时的梯形积分能量和平均功率。`observed_*` 是整机观测变化，`discharging_only_*` 仅在全部观测均为未插电放电时提供；没有应用独占的精确功耗归因。

## 记录与导出

3DoF与续航都会创建独立会话。结束或中止后导出报告至：

```text
Download/RokidTests/<日期时间-随机ID>/
```

包含 `samples.csv`（电池原始采样）、`summary.json`（阶段耗电摘要）、`metadata.json`、`stages.jsonl`（工作负载与开关/回正事件）。3DoF会额外导出 `motion_frames.csv` 和 `motion_metrics.csv`；关闭写入器后再复制，保证最后一批数据完整。元数据包含应用版本、跟随/预测/录制开关、轴向、FOV和会话起始单调时钟。

### 显式录制 IMU

首页将「IMU 录制」切到「开」，再进入3DoF开始本段录制。测试中下方显示「IMU录制中」及原始样本条数；双击返回停止并导出，首页提示保存结果。将录制切到「关」后，后续3DoF不创建IMU文件；电量与帧诊断保持原有记录方式。进入后台也会停止、保存，恢复前台时按当前开关开始新段；重启应用后录制默认关闭。

开启录制的每个会话额外保存：

| 文件 | 数据 |
| --- | --- |
| `imu_raw.csv` | Android加速度计和陀螺仪每次回调：采集时间戳、接收时间、传感器类型、精度状态、XYZ；即使采用系统融合姿态也独立采集六轴 |
| `imu_poses.csv` | 每个有效融合输出：采集/接收时间、数据源、参考系epoch、初始化标记、绝对与相对四元数（x,y,z,w）；相对姿态位于跟随/预测之前，初始化时留空 |
| `imu_metadata.json` | 时钟、坐标、单位、传感器型号/供应商/量程/分辨率、注册结果、最终行数、丢样数、错误与正常关闭标记 |

原始XYZ使用Android设备坐标，保留系统传感器校准，不做应用层滤波或轴向转换；加速度含重力，单位m/s²，角速度为rad/s。时间戳单位ns，与Android启动后单调时钟一致，不要直接当UTC使用。姿态参考系变更以`reference_epoch`分段；回中/维稳事件见`stages.jsonl`，其`elapsed_ms + metadata.json.started_elapsed_ms`可与IMU时钟对齐。

记录使用独立传感器线程及后台CSV线程，申请200Hz、实际频率由硬件与系统决定。每250ms刷新，8192条有界队列满时丢弃新样本并计数，界面显示丢样提示；缺失的原始传感器也明确提示。退出时先停止接收、排空、关闭两个日志写入器，再导出。应用被强制终止或设备断电时只能保留此前已刷新的本地部分数据，不能保证自动导出。录制会增加存储和采集负载，分析性能/耗电时应记录该开关。

可显式使用启动参数（先停止旧进程）：

```powershell
adb shell am start -n com.rokid.stabledemo/.MainActivity --ez follow_enabled false --ez imu_recording_enabled true
adb pull /sdcard/Download/RokidTests ./RokidTests
```

v0.4在保留旧列顺序的基础上追加普通补偿残差/RMS、`prediction_enabled`、`prediction_horizon_ms`、`periodic_hz`、`prediction_strength`、`prediction_delta_deg`。开关为1但强度/时长为0表示设置已开而该帧未应用预测；未识别的频率留空。元数据记录开关、前推设置和限幅策略。

视频、照片以及原始报告保存在应用目录，导出失败时仍保留原件：


## 实现方式与开源依据

- 保留参考 Demo 的画布、安全区、按键和广播事件定义。3DoF路径不启动摄像头或麦克风，媒体硬件仅由续航模式使用。
- 优先使用 Android `TYPE_GAME_ROTATION_VECTOR`，其次 `TYPE_ROTATION_VECTOR`。后一种可能受磁场影响。传感器注册失败、首次数据超时或持续断流时自动尝试下一数据源。
- 无融合姿态时，将眼镜本机陀螺仪与加速度计接入 [x-io Fusion](https://github.com/xioTechnologies/Fusion)，采用 MIT 开源的无磁力计 AHRS 与静止零偏估计。C 源码随仓库固定在 commit `a8d7224f36a0ec82345ef49a3db50e65f8d3bab8`，通过 JNI 运行，包含 arm64-v8a、armeabi-v7a、x86_64。
- 在独立线程读取传感器采集时间戳，绘制时取最新姿态。用四元数逆旋转和透视单应变换补偿整块文字平面，包含偏航、俯仰与横滚；不将欧拉角简单换成像素位移。内容离开视场时自然裁切。
- 按 VSync 由硬件 Canvas 渲染。文字按完整文本预排版，以单调时钟每 90 ms 增加一个 Unicode 字符，全部显示后停留 2400 ms，持续循环。切换模式与回正不重置播放。
- 周期俯仰预测、重力参考、慢回中、内容区投影和诊断为本项目代码；未接入XRSLAM、OpenVINS或Gyroflow源码。显示端仍有传感器、绘制、合成与扫描输出延迟，预测参数需真机校准。

没有加入研究文档中的 SLAM/VIO/Gyroflow：此版本的输入是本机 IMU，目标是虚拟文本方向稳定。

## 真机必须确认的两个参数

**轴向：** 根据用户实机反馈，v0.1中的旧Demo映射会把偏航与横滚交换。v0.2默认使用标准Android屏幕坐标：右X、上Y、朝向佩戴者Z，pitch=X、yaw=Y、roll=Z。若测试另一种旧固件，可显式设置 `axes=demo`，恢复保持右手性的旧基变换 `(x,y,z) → (x,z,-y)`。

**视场角：** 资料没有光学内参或真实 FOV。默认水平30°是待校准的工程初值，不能当作设备规格。参数指480像素显示宽度对应的水平视角；假设方形像素，渲染原点放在内容区中心(240,276)，缩小内容区高度不会改变横向焦距和角度比例。这是应用布局与投影的工程约定，尚未测量光学主点。真实设备若存在光学畸变、非对称投影或显示区映射差异，需替换为测量后的投影参数。

可通过启动参数调整，不增加启动页按钮：

```powershell
# 参数仅作用于这次启动；先停止已有进程再设置。
adb shell am force-stop com.rokid.stabledemo
adb shell am start -n com.rokid.stabledemo/.MainActivity --es axes android --ef horizontal_fov_deg 30

# 强制走 Fusion 原始六轴，用于比较系统融合与开源算法。
adb shell am force-stop com.rokid.stabledemo
adb shell am start -n com.rokid.stabledemo/.MainActivity --ez force_fusion true
```

`axes` 支持 `android`（默认）或 `demo`；FOV 范围为5°..120°，非法值回退30°。需要永久修改时调整 `MainActivity` 默认配置并重新构建。

缩时验收可显式启动 `--ei benchmark_stage_seconds 12`，每项12秒，菜单与报告均标记该时长；未传参数仍是每项300秒。缩时运行只能验证流程，不能替代25分钟真机续航测量。

## 构建与测试

需要 JDK 17+（本机验证为 Android Studio JBR 25）、Android SDK 36、NDK `28.2.13676358`、CMake `3.22.1`。Gradle wrapper 为 9.5.0，AGP 为 9.3.0。首次构建需要下载 AndroidX 和 JUnit。

```powershell
./tools/build.ps1

# 指定本机路径
./tools/build.ps1 -AndroidSdk 'C:/Users/yourname/AppData/Local/Android/Sdk' -JavaHome 'C:/Program Files/Android/Android Studio/jbr'

# 对明确指定的测试设备额外安装和运行仪器测试（含真实媒体的缩时一轮）
./tools/build.ps1 -DeviceSerial emulator-5580
```

脚本执行单元测试、Lint、APK构建、签名验证，并将APK、SHA-256和检查记录写到 `outputs/`。带 `-DeviceSerial` 的仪器测试会实际使用麦克风、扬声器、相机并保存测试媒体，测试媒体音量须非零；完整测试包含12秒×5阶段。原始Gradle产物在 `app/build/outputs/apk/debug/`。输出目录不提交到Git，源代码与固定版本开源依赖提交到仓库。

## 真机检查流程

| 动作 | 应观察到的行为 |
| --- | --- |
| 正视后进入3DoF | 自动回正，绿色中文逐字出现并循环 |
| 小幅左右转头 | 维稳开启时先快速反向补偿，再逐步回到黑色内容区中心；关闭时随眼镜屏幕转动 |
| 抬头、低头 | 文字按相反方向补偿，幅度应与真实视场匹配 |
| 左右歪头 | 文字执行横滚反向旋转 |
| 单击比较 | 播放不重启，状态条显示开／关 |
| 长按 | 文字立即回到当前正前方，横滚补偿继续保留 |
| 跟随开时大幅转头 | 浮窗中心在X偏移超过240像素或Y超过116像素时，直接水平跳回黑色内容区中心 |
| 跟随关时大幅转头/等待/切维稳 | 锚点不变，不超界回中；转回原方向可再次看到，长按才移动到眼前 |
| IMU录制开后进入3DoF，再双击返回 | 测试中明确显示录制状态，返回后停止并导出三个IMU文件 |
| IMU录制关后进入3DoF | 显示录制关，不创建IMU文件 |
| 双击/返回 | 返回五项菜单，停止传感器并保存导出 |
| 切后台再回来 | 重新初始化与回正，避免跨暂停积分 |
| 静止一至五分钟 | 观察静止抖动与航向漂移，记录数据源、采样率与回正次数 |

屏幕上的 Hz 是姿态样本到达频率的估计，**不是端到端延迟或维稳精度**。模拟器验证能够检查代码与交互，不能确认眼镜的光学效果、功耗、真实漂移和运动到显示延迟。IMU 3DoF 不补偿走动产生的位置变化；无可靠航向参考时仍会产生漂移。
